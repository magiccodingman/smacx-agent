# SMACX semantic-agent operating rules

You can control Sid Meier's Alpha Centauri: Alien Crossfire through the `smacx` MCP tools.

- Use only structured observations, enumerated legal choices, and semantic commands.
- When launch mode or platform support is uncertain, query one compact `smac_capabilities` section. Treat `not_implemented` and `external_certification_required` as hard boundaries, not invitations to use the UI. Fresh `smac_decision`/`smac_choices` output remains the authority for the current game state.
- Use `smac_reference(action="topics"|"search"|"get")` when a game mechanic is unclear. Search is compact and citation-bearing; fetch only the exact returned document needed. General reference knowledge never overrides fresh native choices or reveals hidden match state.
- Prefer compact `smac_decision` as the ordinary loop. It atomically bundles a stable player-state headline with the mandatory active interaction, one ready unit's exact choices, a wait/gap directive, or game-management choices. Execute at most one returned command, discard the frame, and call it again. Use `detail="full"` for at most one strategic decision when the complete snapshot is genuinely necessary; never use it as the per-unit default.
- Never use screenshots, computer vision, mouse coordinates, keyboard events, raw text-entry simulation, desktop automation, or terminal-driven UI control.
- Never use scenario-editor omniscience, memory inspection, hidden factions, or out-of-game save parsing to gain information a human player could not see.
- Treat identifiers returned by the bridge as opaque, per-state choice IDs. Each snapshot's `ready_unit_refs` gives current actionable unit IDs, names, opaque `tile_id` positions, and compact roles; use those IDs to request `unit_actions`. Never perform arithmetic on a `tile_id`, infer adjacency from its numeric value, or invent one: obtain target IDs only from fresh fair-play lists or choices. Refresh state/choices after every material action rather than guessing IDs, and never infer a consecutive or replacement unit ID.
- Advanced governor policy is one named toggle at a time. Use only a fresh `set_governor_permission` tuple and its opposite `active` value. If an active governor manages production, the returned `will_recalculate_production` warning means the native governor will clear future queue entries and immediately choose again; re-list the base afterward. The setting also becomes the default for future new bases.
- Every mutating command must copy `match_id`, `session_id`, and `revision` from the latest `smac_snapshot` into the command's `match_id`, `session_id`, and `expected_revision` fields. Never reuse a guard after any action or wait, even if a later observation appears to have restored the same game state; accepted mutations advance a monotonic bridge generation.
- Follow the interaction state machine exactly:
  - `popup`, `endgame_presentation`, `first_base_name`, `research_priority`, or `research_choice`: call `smac_choices(kind="interaction")`, execute one returned command, then snapshot again.
  - `human_diplomacy`: call `smac_choices(kind="interaction")`, review its complete structured offer and acceptance state, execute at most one returned command, then snapshot again.
  - `turn`: inspect owned bases/units, call the relevant typed choices tool, execute at most one returned action, then snapshot again.
  - `waiting_for_engine` or `waiting_for_turn`: call `smac_wait`; do not issue a command.
  - `unsupported_modal`: report a capability gap and stop.
- A `stale_state` or `wrong_game_identity` response means no action was applied. Take a fresh snapshot; never retry by changing IDs or arguments from memory.
- For a deferred native action, trust `completed`/`execution.status`, not the initial `queued` flag. If it remains pending after the MCP's bounded wait, wait and inspect `snapshot.last_deferred_action`; never overlap another action. A `native_action_rejected` result means re-observe and choose a different returned action.
- `convene_council` intentionally remains pending while its native proposal list is open. Resolve `COUNCILISSUES` with the returned `choose_council_proposal` and its bundled candidate or YEA/NAY ballot, then observe `last_council_result`. Do not issue unrelated turn actions during a staged interaction.
- For Unit Workshop decisions, call `smac_choices(kind="unit_design")`; use only returned component/prototype IDs. Never reuse its guard after creating, retiring, or upgrading a design. Retirement and upgrades require the explicit confirmation parameter returned by the choice contract.
- A ready vehicle may expose `upgrade_unit` separately from the Unit Workshop's all-units upgrade. Copy only an exact target and price returned by that vehicle's fresh `unit_actions`, deliberately set `confirm_upgrade=1`, then observe again; the command changes one unit, spends energy, and consumes its turn.
- If `ASKSEEDESIGN` offers the workshop, `respond_to_design_offer(response="open")` closes the coordinate-oriented window and hands off to `smac_choices(kind="unit_design")`; take a fresh snapshot before opening those choices.
- Treat boarded passengers as their own state: choose `remain_boarded` or one returned `disembark_unit` target. For air drops and artillery, use only a target bundled with the unit's fresh choices, then observe immediately; artillery combat may shift unit IDs.
- Carrier recovery is object-targeted. Choose an owned carrier from fresh unit state, then call `unit_actions` with both the aircraft `unit_id` and carrier `target_unit_id`. Use only a returned `recover_to_carrier` or `board_carrier` tuple. Recovery reserves deck capacity and mechanically holds the carrier; do not attempt generic `go_to` to its tile or command the carrier while `reason="carrier_recovery_lock"`. After arrival, board before moving the carrier. Re-list both units after any turn or movement because native vehicle IDs can shift. A boarded aircraft may `remain_boarded` or use its returned `activate_unit` launch choice.
- Missile targeting is two-stage. Read the compact `target_query`, choose only a `tile_id` from fair-play semantic state, then call fresh `unit_actions` with that `target_tile_id`; launch only an exact returned tuple. A Planet Buster additionally requires a deliberate `confirm_atrocity=1`. Re-list units after every launch because the missile is consumed and IDs may shift.
- For a probe team, execute only an exact `execute_probe_mission` tuple returned by its fresh `unit_actions` choices. Copy the target base/tile object IDs, action, mode, and frame fields together, set `confirm_probe_incident=1` only after selecting that incident, then observe until the deferred native action finishes.
- Targeted sabotage is a staged deferred probe action. Its initial tuple contains no facility knowledge. If `VIRUS` appears, choose only a target returned by the fresh interaction; if `MILVIRUS` or `HQVIRUS` follows, choose abort or proceed from that fresh warning. Do not issue another turn action until the original probe action completes.
- Genetic plague requires both returned incident and atrocity confirmations. A captive-leader rescue tuple contains no captive identity; only choose a faction returned later by the native `FREEWHO` interaction, and do not overlap the pending mission.
- For a loan interaction, review direction, principal, payment, term, scheduled total, and affordability together. Use only the returned accept, reject, or half-principal counteroffer, then re-list factions to read the native debt ledger.
- For technology commerce, use only the named technology and exact price from the active interaction. An alternate sale is legal only when that fresh tuple returns it. Re-list technologies and observe energy after acceptance; do not assume transfer success from button submission alone.
- A joint-attack counteroffer names the exact target and either an energy price or the complete bundle of one to four owned technologies. Reject freely; accept only the fresh complete tuple, then observe the native Vendetta outcome and treasury before planning another action.
- Diplomacy proposal and target menus use native semantic IDs that are not row numbers. Select only an exact returned `choose_diplomacy_option`, `choose_diplomacy_target`, or `choose_diplomacy_base_target` tuple. A commlink/prototype purchase must be decided from its fresh named target/design, quoted price, and affordability; re-list factions or Unit Workshop designs after acceptance.
- Human LAN diplomacy is a paired native state machine. Open only an exact fresh human-controlled target from `smac_choices(kind="diplomacy")`, then re-observe: stock `0x1502` has no receiver-ready acknowledgment, so a fully returned no-window collision requires a newly enumerated retry, never replay. In `human_diplomacy`, review participant IDs, acceptance state, and every structured clause. Use only returned proposals: `propose_human_relationship` enforces Treaty/Pact/Truce prerequisites; `propose_human_technology` names an exact currently owned technology the peer lacks; `propose_human_energy` accepts only an `amount` inside its fresh `amount_min`/`amount_max` treasury bound; `propose_human_joint_attack` names only a returned live third faction already contacted by the caller. Each proposal atomically composes, network-drains, verifies, and commits the complete outgoing offer; do not issue a second proposer-side accept. The peer must observe every synchronized clause and then use one fresh accept or decline choice. On `stale_state`, re-enumerate and proceed only if the identical intended choice remains present. Never accept twice, edit an accepted offer, infer a clause, exceed the returned amount bound, or treat `finish_human_diplomacy` as acceptance; it only ends a still-open transmission. Resolve a resulting `technology_presentation`, then wait through the mandatory `waiting_for_engine` settlement phase and re-observe ownership/treasuries/relations. The paired-human native record has no map clause; map exchanges belong to typed AI negotiations.
- In LAN, an AI `COMM`/`COMMDIPLO` prompt is local to the active human client. Accept only when that exact fresh choice is returned, continue each `INTRO*` greeting, acknowledge only returned reviewed passive notices (including `TIMEWARNING`), and use `DIPLO` `finish` to close the channel. A fresh brokered `INTRODUCE`/`METFRIEND`/`METFRIEND2` commlink offer may be accepted or rejected only through its returned `respond_to_diplomatic_offer` tuple. Fully described technology trades/demands and Treaty/Truce/Pact offers may be rejected safely when that response is returned. Do not accept a transfer, concede technology, or invent another AI bargaining response: other consequential multiplayer bargains remain mechanically blocked until their synchronized effects are validated.
- The `COUNTER1` gift-type menu exposes an exact-bounds `give_energy_gift` choice for energy payments. Copy only an amount within that fresh tuple; the bridge drives the nested native amount/receipt sequence atomically and verifies both treasury deltas. Never call the generic `choose_diplomacy_option` for `energy_payment` or infer an amount.
- Do not invent a proposal-menu `offer_units` action. Although `Script.txt` contains that text row, the executable never inserts it into `PROPOSAL`; native ID 12 belongs to the separate Council-vote request path. Direct transfer is supported only when an eligible unit's fresh `unit_actions` family returns confirmation-gated `give_unit` in visible Pact territory.
- A negotiated base transfer names the exact native base and either an energy price or the commitment to share every owned technology. Accept only a fresh affordable tuple, then re-list bases; capture can change base IDs and strategic state.
- A pre-vote Council bargain names the requested ballot and exact price. Choose only a returned `payment`: `none`, affordable `energy`, or the complete returned technology bundle. Never substitute a different technology or infer a partial bundle.
- An incoming `VOTEFORME` or `VOTEFORMETECH` bargain names the candidate and exact energy or two-technology payment offered for the player's Governor ballot. Reject freely, or copy the candidate and `confirm_vote_commitment=1` only after deliberately accepting that exact fresh bargain; then observe the Council state and received payment.
- A territorial or hostility popup may be the middle stage of a pending movement/combat action. Use only its fresh `respond_to_territorial_incident` choice; copy `confirm_hostility=1` only after deliberately selecting refusal, proceed, or declaration. Do not queue another action until the original deferred `action_id` completes, then re-list factions and units.
- A Nerve Gas Pod attack may open `USENERVE` during that same deferred combat action. Use `respond_to_nerve_gas(response="conventional")` for the safe ordinary attack. Use `response="commit"` only after deliberately choosing the atrocity and copy the independently returned `confirm_atrocity=1`; never infer or silently supply it. Continue tracking the original `action_id` and resolve any resulting notices before another turn action.
- An Alien Artifact entering an owned base may open `ARTIFACT`. Use only a fresh `respond_to_artifact` tuple. `no_action` preserves it; linking for a technology or accelerating the exact named Secret Project/unprototyped unit permanently consumes it and requires `confirm_consume_artifact=1`. Resolve any following technology notice and wait for the originating move `action_id` to complete.
- Treat `execute_probe_subversion` the same way: copy the returned target unit, position, mode, and quoted cost together. Never infer a cost or target a unit absent from fresh choices.
- Use only a returned `use_psi_gate` destination. A successful transfer consumes both endpoint gates for that turn, so observe and do not expect another transfer from the destination.
- `auto_explore_unit`, `set_unit_on_alert`, `automate_air_defense`, `automate_former`, `set_bombing_run`, `go_to_base`, `return_to_base`, `patrol_unit`, `go_to`, and `build_road_to` create persistent native orders or policies. Explore, Air Defense, bombing runs, and named Former modes delegate future decisions to native player automation; that policy may move, lose, or remove the unit. A bombing run must copy one exact visible Vendetta-base `target_tile_id` returned by fresh choices; never fabricate a target, and treat its round-trip fuel guard as authoritative. `return_to_base` takes its exact returned base ID. `go_to_base` queries a known owned `base_id`; other destinations query an opaque `target_tile_id`. A fuel-limited aircraft's returned `go_to` tuple is classified as `air_recovery` to a visible friendly base/standalone airbase or `air_round_trip` to a non-refueling destination; never fabricate a generic route to bypass those range checks. The bridge alone resolves native coordinates and validates triad access, patrol rules, terrain, and aircraft fuel safety. Once ordered, do not command that unit again unless fresh choices expose `activate_unit`; ordered units are intentionally excluded from the end-turn decision count.
- Choose a Former policy only from its fresh `automate_former` tuples; technology- and support-dependent modes are deliberately absent when invalid. Automation can change state asynchronously, so a resulting `stale_state` on another unit means re-observe. Do not confuse patrol with automation even though the native engine shares an internal flag—the semantic `order_name` and choices are authoritative.
- `set_designated_defender` is a non-turn-consuming native combat-role toggle. Use only the exact opposite 0/1 value returned by fresh `unit_actions`, observe again, and then make the unit's movement decision with the new revision. Never repeat or guess the current flag.
- `destroy_terrain_improvement` is permanently destructive. Use only an exact fresh improvement tuple, copy `confirm_destruction=1` deliberately, and copy `confirm_hostility=1` only when that same tuple marks peaceful foreign territory. The native layer order is authoritative: remove a Soil Enricher before its Farm and a Mag Tube before its Road. Pact territory is unavailable. Wait for the deferred action to complete, then observe again.
- `self_destruct_unit` permanently destroys its source and damages every non-base stack on its tile and adjacent tiles. Review the fresh `known_affected_units` list, remembering that ordinary fog still hides unseen collateral, and copy `confirm_self_destruct=1` only after deliberately accepting the overload. Re-list all units afterward because multiple units can die and IDs can shift. The action is not available in LAN until its packet path is validated.
- Never synthesize `end_turn`. Request fresh `game_management` choices after resolving unit decisions and use it only if `turn:end` is returned. `turn:end_blocked` is information. If—and only if—you deliberately decide that every listed ready unit has no further useful action this turn, call `smac_decision(finish_ready_units=true)` and copy the exact `skip_all_ready_units` tuple, including its count and `confirm_skip_all_ready=1`; native preferences may immediately advance the turn. Otherwise resolve units individually. Never invent a batch or use skip-all just to reduce calls. If native automation produces `REALLYOVER`, use one fresh `respond_to_end_turn_confirmation` choice. A following `turn:transition_pending` means wait and forbids another mutation until the turn changes or a fresh mandatory interaction appears; that enumerated interaction supersedes the wait and must be resolved first.
- During `endgame_presentation`, copy the exact returned `phase` into one `advance_endgame_presentation`, then observe again. Do not issue unit, base, diplomacy, save, or turn mutations while credits, score, Quayle, Hall of Fame, replay, or a victory interlude is active. `GAMEOVERMAN` is a later decision: use only its fresh finish/continue tuple. Default autonomous launches set `narrative_ui=false`, disabling optional external movies that do not have semantic controls.
- Read structured base-status or production-completion context before acknowledging its popup, then re-list that base. Treat the notice as an event, not as proof of the complete resulting base state.
- `nerve_staple` is an atrocity. Use it only from a fresh base-management choice after a deliberate strategic decision, and copy `confirm_atrocity=1`; never infer or silently supply that confirmation.
- `recycle_facility` permanently removes a built facility. Use only the exact fresh tuple after reviewing its refund and copy `confirm_recycle=1`; never infer that confirmation, and re-observe the base immediately afterward.
- Keep all notes and learned player information scoped to the returned `match_id`. Never transfer unverified match-specific facts into another match.
- Durable knowledge must not contain session-local engine object references. Never write unit, vehicle, base, or prototype IDs (including prose such as `(id 26)` or `base 0`) into `smac_knowledge`; those can shift after native processing or reload. Record stable names, relationships, behavior, and match-local observations instead. The tool mechanically rejects obvious ephemeral references.
- Use `smac_knowledge(action="put")` for durable match facts, copying the current `match_id`, `session_id`, and snapshot `revision`. Use stable keys and overwrite a key only to correct or update the same fact; the ledger preserves its prior revisions. Do not use general filesystem notes for match-specific intelligence.
- If a necessary observation or action is absent, call `smac_report_capability_gap` once with the exact state, intended decision, data needed, and action needed. Then stop. The MCP latches that exact match/session and rejects every later `smac_command`, launch, new game, or load; there is no agent-callable clear operation. Play resumes only after the bridge has been extended and tested, the developer restarts MCP, and a fresh native session begins. Do not invent a workaround.
- The visible game is a spectator display. It must reflect the semantic actions, but it is never an input source for the agent.
- Colony Pods found bases. Formers terraform and cannot found bases. Move a Colony Pod off an existing base and use a fresh `unit_actions` choice when seeking a legal settlement site. Founding consumes the pod and may shift later unit IDs, so re-list units before issuing another unit action.
- When `unit_actions` returns `settlement:unavailable`, treat it as non-executable native rule status. Use its fair-play reason and base-range fields to reposition the Colony Pod; never fabricate `found_base` while it is absent.
