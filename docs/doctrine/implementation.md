# Dynamic gameplay doctrine

The managed profile contains one exact system message: operational v6 contract, then Sovereign Gameplay Doctrine with the 16 reviewed placeholders expanded in place, then the optional personality layer. Runtime context remains a separate request-only tail. The generator guide, fingerprints, raw settings and compatibility diagnostics are private control-plane provenance. No managed tool was added.

The native UI-thread `doctrine_context` operation returns an authenticated seat/session-scoped public receipt. Rule-file identity is captured around successful native rule loading, not guessed from a filename at prompt time. The receipt also checks the reviewed native source build, unchanged loaded core rules, supported configuration and scenario conditions. The control adapter projects public faction rules and fixed match conditions into `smacx.confirmed-gameplay-context.v1`. See `input-manifest.json` for all 16 blocks, input classifications and native sources.

`smacx_doctrine.py` owns reviewed deterministic prose. Version `smacx.sovereign-doctrine.v1`, compiler `smacx.doctrine-compiler.v1`, and compatibility family `thinker-smacx-doctrine.v1` are persisted with doctrine, operational, loaded-rule, configuration and final-prompt hashes. Existing `harness_profiles.system_prompt` and metadata hold the exact text and manifest; seat metadata holds the confirmed context. No schema change or database reset is needed.

Profile preparation requires confirmed native context. Both managed prepare/run endpoints collect it through the owned worker before assembly. An unchanged assembly signature returns the stored bytes after integrity verification. A changed fixed contract, doctrine, operational content or personality requires the authenticated operator's explicit `recompile_doctrine: true`. Existing operational-only profiles also require this explicit transition. Current turns, technologies, diplomatic changes, units and newly discovered opponents never become compiler input. Opening conditions and the initial public roster are frozen; changing current observations belongs in runtime context.

Unknown required values, unsupported faction bonuses, unreviewed engine builds/rule files, material scenario overrides and corrupted persisted text fail with named `doctrine_*` diagnostics. There is no automatic stock fallback for missing fields. Supported custom faction modifiers are typed public facts, not arbitrary custom rules prose. The initial compatibility boundary is intentionally narrow: arbitrary modified alphax files, gameplay INI overrides and unsupported material scenarios require further review. Future native source changes require explicit review and `scripts/doctrine_engine_contract.py --register-reviewed`; registration is never performed by the production runtime.

A complete public roster is optional. If any participating faction is not legitimately known at first assembly, opponent roster and density are omitted. The model can learn opponents through normal fair-play runtime evidence. Map context is a generation prior; the native rectangular area convention is documented in the acceptance ledger. Imported positions omit inapplicable opening advice.

The context policy reserves at least 12,000 tokens for system/tools, increasing to `ceil(system UTF-8 bytes / 3) + 8192` when larger. This is conservative capacity planning, not exact tokenizer output. Exact measurements are kept separately. Assembly rejects windows that cannot also leave the normal response/reasoning reserves and 8192 history tokens. The strict provider hook independently enforces this reserve from the actual hashed prompt. Existing GC/compression policy ratios remain unchanged.

Authority remains: verified loaded mechanics, current legal choices and authoritative harness evidence outrank general doctrine. Faction mechanics are affordances; personality cannot redefine mechanics or prescribe a fixed strategy. Principle-based strategy stays in the sovereign, with no action ranking, build orders, hidden agendas or parallel world model in the compiler.
